# Ivy Archive — System Design

**Status:** Draft  
**Date:** 2026-06-20  

---

## Purpose

Ivy is the archive. She knows where you were, what you were doing, and how to get back.

The system has one job: given any question about past work, return a navigable answer —
repo, branch, file, next action. It should be possible to start from ivy and land back
in a working session with full context restored.

---

## Overview

```
[session] → save context → .scratch/[file].md
                                  ↓
                           ivy sweep (stamp)
                                  ↓
                           ivy collect → ~/Documents/ivy-archive-private/ (git repo)
                                  ↓
                           ivy groom  → merge duplicates within git repo
                                  ↓
                           ivy push   → git remote (GitHub private) + NotebookLM
                                  ↓
                        [work concludes]
                                  ↓
                           ivy conclude → summary → concluded/ → push both destinations
```

---

## Components

### 1. Source Files

Generated by `save-context` skill in `.scratch/` directories within each project repo.

**Location:** `[repo-root]/.scratch/[filename].md`

**Filename convention:**
- `[TICKET]-context-[YYYY-MM-DD].md` — if branch has ticket prefix
- `session-context-[YYYY-MM-DD].md` — no ticket
- `main-context-[YYYY-MM-DD].md` — auto-generated on pre-compact

**Key fields in each file:**

```markdown
Generated: [ISO timestamp]
Branch: [branch-name]
Status: [discovery|in-progress|review|blocked]
Description: [one-line summary, max 12 words]

## Objective
## Where Things Stand
## Next Actions
```

**Stamp appended by ivy sweep:**

```html
<!-- Swept: 2026-06-20T18:36:44Z | Pushed-to-ivy: never -->
```

---

### 2. Local Git Repo: ivy-archive-private

**Location:** `~/Documents/ivy-archive-private/`

The central collection point. All context files from all repos are copied here,
organized by repo name. This is a private git repo pushed to a GitHub remote.

**Structure:**

```
ivy-archive-private/
  woven/
    main-context-2026-06-20.md
    main-context-2026-06-17.md
    session-context-2026-06-13.md
  dev/
    session-context-2026-06-13.md
  skill-map/
    skill-map-context.md
  captains-log/
    captains-log-2026-06-16.md
    captains-log-2026-06-12.md
  concluded/
    woven-main-CONCLUDED-2026-06-20.md
    woven-feature-auth-CONCLUDED-2026-05-31.md
```

**Backlink mechanism — provenance header:**

When ivy collects a file into this repo, it prepends a provenance block:

```markdown
<!-- ivy-provenance
source_path: /Users/dhk/Documents/dev/woven/.scratch/main-context-2026-06-20.md
repo_path:   /Users/dhk/Documents/dev/woven
repo_name:   woven
git_remote:  git@github.com:dhk/woven.git
branch:      main
collected:   2026-06-20T18:45:00Z
-->
```

This is the answer to "how do I get back?" — every file in ivy-archive-private knows
exactly where it came from and which repo/branch to return to.

---

### 3. Remote Git Repo

**Location:** GitHub private repo (URL stored in `~/.claude/skills/ivy-archive/config`)

Pushed from `~/Documents/ivy-archive-private/` via standard `git push`.

Purpose:
- Durable off-machine backup
- Version history of all context snapshots
- Accessible from any machine

---

### 4. NotebookLM: ivy-archive-private

**Notebook:** `ivy-archive-private` on notebooklm.google.com

Files from `~/Documents/ivy-archive-private/` are added as sources. Because the
provenance header is embedded in each file, NotebookLM queries can surface not just
what the work was, but where to go to resume it.

**Append-only:** sources are never deleted. The notebook is a permanent record.

When work concludes, a Work Summary is added as an additional source alongside the
individual snapshots — not replacing them.

---

## Backlink: Working Backwards from ivy-archive-private

The primary use case: you open ivy in a new session and ask "what was I working on?"

**Query flow:**
1. User asks: `"ivy, what branches are active on woven?"`
2. Ivy searches (local grep or NotebookLM)
3. Finds `woven/main-context-2026-06-20.md` in ivy-archive-private
4. Reads provenance header → extracts `repo_path`, `branch`, `source_path`
5. Returns:

```
Ivy says:

Active work on woven/main:
Description: Progressive disclosure + join-in mode
Status:      in-progress
Last seen:   2026-06-20

── To resume ──
Repo:    ~/Documents/dev/woven
Branch:  main
Context: ~/Documents/dev/woven/.scratch/main-context-2026-06-20.md

cd ~/Documents/dev/woven
git checkout main
# Then in that session: /resume-context
```

The provenance header makes this deterministic — no guessing, no fuzzy matching on
repo names. The path is embedded in the file.

## Modes

### `sweep archive` (fast, local)

- Find new/changed `.scratch` files across `~/Documents/dev`
- Append/update stamp: `<!-- Swept: ... | Pushed-to-ivy: never -->`
- Update `.last-sweep` timestamp
- No git, no NLM calls

### `ivy collect`

- Copy `.scratch` files and captain's logs into `~/Documents/ivy-archive-private/`
- **Prepend provenance header** to each collected file
- `git add -A && git commit -m "ivy collect — YYYY-MM-DD HH:MM PST"`
- On first run: `git init`, prompt for GitHub remote URL, save to config

### `ivy groom`

Operates within `~/Documents/ivy-archive-private/`.

**Duplicate detection** per repo subfolder:
- Same `Branch:` field → merge
- Same `Description:` (fuzzy, ~80% match) across dates → consolidate

**Merge output:**
- Most recent `Where Things Stand` and `Next Actions`
- Combined `Technical Decisions` and `Warnings` (deduplicated)
- `Generated:` = most recent timestamp
- `## History` section added: lists all dates merged
- Provenance header updated: lists all source paths merged
- Commit: `"ivy groom — merged N files across M repos"`

### `push to ivy`

Two destinations:

**A. Git remote:**

```bash
git -C ~/Documents/ivy-archive-private push origin main
```

**B. NotebookLM:**
- Scan files in `ivy-archive-private/` for `Pushed-to-ivy: never` or stale stamp
- Add each via `mcp__notebooklm__source_add`
- Update stamp: `Pushed-to-ivy: [timestamp]`
- Commit stamp updates

### `ivy conclude [repo]`

Mark a work stream complete.

1. Find all active files for `[repo]` in `ivy-archive-private/[repo]/`
2. Generate Work Summary:
   - What was built (from Objectives)
   - Key decisions (Technical Decisions)
   - Outcome / final status
   - Date range active
   - Links to all source files (from provenance headers)
3. Write to `ivy-archive-private/concluded/[repo]-[branch]-CONCLUDED-[date].md`
4. Move individual files to `ivy-archive-private/concluded/[repo]/`
5. Commit + push to remote
6. Add summary to NotebookLM (individual files stay — append-only)

### `ivy status` / sync status check

Check whether the current session's context is current in ivy.

Reads the stamp in `.scratch/[file].md`:
- No stamp → never swept
- `Pushed-to-ivy: never` → swept but not in NLM
- `Pushed-to-ivy` < file mtime → pushed but stale
- `Pushed-to-ivy` ≥ file mtime → fully current

### Query mode

Two backends:

**Local grep (default):**
- Keywords extracted from question
- `grep -ril` across `ivy-archive-private/**/*.md`
- Read provenance header from matches → extract repo_path, branch, source_path
- Return navigation-ready answer

**NotebookLM (`--nlm`):**
- Semantic search via `mcp__notebooklm__notebook_query`
- Answer includes provenance info when available
- Requires push to have run

## Config File

`~/.claude/skills/ivy-archive/config`

```
local_repo=~/Documents/ivy-archive-private
remote_url=git@github.com:dhk/ivy-archive-private.git
```

Created on first `ivy collect`. Skill reads this at the start of any mode that touches
the git repo.

## Typical Session Workflow

**Starting fresh in the morning:**

```
ivy, what was I working on yesterday?
→ Returns: repo, branch, context file path, next actions
→ cd ~/Documents/dev/woven && git checkout main
→ /resume-context
```

**End of a session:**

```
save context
sweep archive        ← optional, stamps immediately
```

**Weekly maintenance:**

```
ivy collect          ← gathers everything into git repo
ivy groom            ← merges duplicates
push to ivy          ← git push + NLM update
```

**Work complete:**

```
ivy conclude woven   ← generates summary, archives, pushes
```
